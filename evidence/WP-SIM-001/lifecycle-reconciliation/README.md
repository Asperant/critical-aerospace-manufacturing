## Codex review R1 and R2 (CHANGES_REQUESTED) — addressed

- **R1, cached GitHub rechecks.** Confirmed: the adapter caches every GET, so the pre-write
  "recheck" re-read `main`, the branch refs, comparisons and file pages from cache, and the PR
  identity predicates ran on a cached object. Fix: `GitHub.invalidate()` drops every cached read
  except immutable SHA-addressed commits; `gather` calls it first, so each of the two snapshots is
  fresh; all PR predicates run on the one fresh object; the audit records the second snapshot
  (closest to the write, including the newly observed main). Legitimate main advancement is still
  accepted because reachability is proved against the newly observed main. New tests run the real
  adapter with changing transport answers: a force-moved main, a recreated branch, a same-count
  inventory change, a changed PR author/head/merge/title/base/state and a changed run each block the
  write with no PATCH and no INTENT row.
- **R2, owner queue.** Confirmed: only the target WP was validated. Fix: a write is refused
  (`OWNER_QUEUE_CONFLICT`) while the same owner has another READY or IN_PROGRESS item, at entry and
  again after a fresh queue read immediately before the write
  (`CONCURRENT_OWNER_QUEUE_CHANGE`). BACKLOG, review, merged, finished or other members' items are not
  conflicts, nothing is selected or changed, and a verified no-op is exempt (after a reconcile the
  owner normally has a next READY item).
- **Compliance re-audit hardening.** The audit noted that the last full Plane comparison happened
  before the second GitHub snapshot. The final Plane read and equality check now come last, so a
  change to the item during the recheck window blocks the write (`CONCURRENT_PLANE_CHANGE`) instead
  of being overwritten; a test races a Plane edit into that window and a mutant restoring the old
  order is caught.

   rewritten; they refer to this change's draft number. Identifiers are never reused once published.
2. **CHG-031 owner and status**: the record is `DRAFT` / `UNDER_REVIEW` with `owner: Batuhan`.
   The owner field and the decision are for the governance owners to confirm; the supervisor
   answers are cited as the basis but are not treated as approval of the record itself.
3. **Registry CSV**: `09_change/change_requests.csv` stops at CHG-021 while CHG-022..030 exist
   only as YAML; a CHG-031 row was added anyway. `projectctl validate` accepts it.

   precedent and the plan's "narrow" scope; `AGENTS.md` was not touched (the CHG-019 precedent

5. **Ordinary-flow side effect**: the pagination fix is in the shared adapter, so ordinary
   `cap-plane-transition` flows now accept PRs of 100 to 1000 files (they were rejected before).
   The plan asks for this; edges, predicates and the DONE validator are unchanged.
6. **Installer scope**: extending `install_auto_next.py` means one reviewed deployment path, but
   a refresh also reinstalls the other AUTO_NEXT files from merged source and re-enables the
   health and prepare timers, as that installer already does. The separate root installation
   proposal and authorization must review this; nothing was installed.
7. **Policy hashes**: the generated policy's `policy_digest` and file hashes change with any
   merged-source change, so the installation proposal must be regenerated from the merged
   revision, not from these dry-run values.
8. **Interpretation of "ambiguous membership/WIP"**: duplicate or missing canonical mapping, assignee or
   owner mismatch, any BLOCKED label, and another READY or IN_PROGRESS item of the same owner (AGENTS.md
   section 20: multiple IN_PROGRESS or READY candidates need planning-owner resolution). This is a
   conservative reading; the planning owner should confirm it. Because it applies at write time, a
   live application will be refused while Batuhan has a second READY or IN_PROGRESS item.
9. **Environment**: tools ran from a `uv` environment outside the repository
   (`UV_PROJECT_ENVIRONMENT`); CI uses `ci/.venv` from the same lock. Captured output is
   normalized (trailing whitespace stripped, the session scratch path replaced by `<scratch>`).
